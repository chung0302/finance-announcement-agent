# 基于大语言模型的上市公司公告风险识别与解释助手

> 副标题：面向个人投资者的公告要点提取、风险提示与证据回溯
> 课程：《财经智能体开发与应用》 · 提交截止 2026-11-15

一个中文单页 Web 应用：粘贴公告文本或上传文本型 PDF/TXT 后，自动完成**文本清洗 → 信息抽取 → 知识检索 → 风险识别 → 证据校验 → 二次自检**，输出一句话结论、关键事实、风险标签与等级、风险解释、原文证据、信息不足提示与置信度，并支持导出 Markdown / JSON。

**本工具只做财经信息分析，不预测股票价格，不提供买入、卖出或持有建议。**

## 一、快速开始

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. 启动应用（无需 API 密钥即可启动）
python -m streamlit run app.py

# 3. 运行测试
python -m pytest

# 4. 运行评测（演示模式，无需密钥）
python evaluations/evaluate.py --mode demo
```

Windows 一键启动（推荐**双击 `start.bat`**，它会用 Bypass 策略调用 `start.ps1`）：

```bat
start.bat
```

或在命令行里：

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

> 直接双击 `.ps1` 常被 Windows 执行策略拦截（本机实测会报 `PSSecurityException`），
> 所以才提供 `start.bat` 作为入口。脚本会依次尝试 `PYTHON_BIN` → 项目 `.venv` →
> PATH 中的 `python`，并**实际试运行**每个候选（Windows 商店的 `python.exe` 是占位符，
> 直接调用会失败），最后做依赖自检，缺包时打印具体安装命令而不是抛异常。

启动后浏览器打开 http://localhost:8501 。端口被占用时：
`python -m streamlit run app.py --server.port 8502`

## 二、两种运行模式

| | 演示模式（demo） | 真实模型模式（llm） |
| --- | --- | --- |
| 触发 | 未检测到 `LLM_API_KEY`，或界面手动选择 | 检测到 `LLM_API_KEY` 且接口可达 |
| 抽取/判定 | 确定性规则（正则 + 知识库触发词） | 大语言模型（三个提示词） |
| 界面标注 | 橙色横幅："演示模式，非模型输出" | 蓝色横幅：真实模型模式 + 模型名 |
| 用途 | 课堂演示、离线自测、脚本验证 | 真实效果评测 |

**切换方式**：把 `.env.example` 复制为 `.env`，填入三项配置后重启应用，无需改代码。

```ini
LLM_BASE_URL=https://api.openai.com/v1
LLM_API_KEY=sk-...
LLM_MODEL=gpt-4o-mini
```

**关键约束**：
- 应用启动**不依赖**密钥；模型不可用（超时、返回非法 JSON、网络失败）时自动降级为演示模式并给出告警，不会崩溃。
- 密钥只从环境变量 / `.env` 读取，**不写入任何源码、日志或产物文件**；界面只显示脱敏后的密钥。
- 演示模式的结果在界面与导出文件中均被强制标注，**不得当作模型输出引用**。

## 三、功能清单

- 输入：粘贴文本 / 上传文本型 PDF / 上传 TXT / 一键载入 2 个演示样例（一利好、一风险）
- 结构化抽取：公司名称、公告标题、公告日期、证券代码、事件类型、关键指标或金额、同比变化、缺失字段
- 风险类型：业绩预增或扭亏、业绩预减或亏损、股东或高管减持、重大诉讼或仲裁、对外担保或资金占用、审计意见异常或其他监管风险
- 风险等级：低 / 中 / 高 / 信息不足
- 每条结论区分**事实（原文直述）/ 推断 / 不确定性**，并给出置信度
- 证据校验：已验证证据（绿）与未通过校验（红）分区展示，显示匹配方式与相似度
- 信息不足提示 + 需人工复核标记
- 二次自检：一致性核对、幻觉数字检查、投资建议清理，输出问题清单
- 导出：Markdown 报告 / JSON 结果
- 错误处理：空输入、无文本层 PDF（扫描件，明确报错不做 OCR）、模型超时、模型返回非法 JSON

**明确不做**：登录权限、支付、多用户后台、实时行情、自动爬虫、股价预测、复杂数据库。

## 五、评测

对比两组方案：

- **A（基线）**：普通大模型直接总结（`prompts/baseline_summary.md`，无 Schema、无知识库、无证据校验）
- **B（本作品）**：结构化抽取 + 知识库 + 证据校验 + 二次自检

指标：风险类型识别准确率、关键数字提取正确率、引用覆盖率、无依据结论率、平均响应时间。

**关键数字口径**：「关键数字提取正确率」以标注中的全部数字为分母（含「上年同期」对比基数）；`关键数字提取正确率_本期口径` 只统计本期结论性数字。系统按设计只抽本期值，所以前者会因为「正确地排除了同期基数」而被扣分，两者在 `comparison.csv` 中一并给出。

**真实模型实测（2026-11-04，deepseek-chat，温度 0，14 个样本）**

| 指标 | A 普通大模型直接总结 | B 本作品工作流 |
| --- | --- | --- |
| 风险类型识别准确率（完全匹配） | 0.79 | **1.00** |
| 风险类型识别准确率（至少命中） | 0.79 | **1.00** |
| 关键数字提取正确率 | **1.00** | 0.92 |
| 关键数字提取正确率（本期口径） | **1.00** | 0.98 |
| 引用覆盖率 | 0.00 | **1.00** |
| 无依据结论率 | 1.00 | **0.00** |
| 平均响应时间 | **2.05 秒** | 11.56 秒 |

结论要如实讲：B 赢在**类型判定更稳**与**每条结论都能回到原文**（74 条证据全部通过校验），代价是延迟约 5.6 倍；**数字召回 A 略优**，因为 A 可以把"上年同期"等数字一并列出，而 B 按设计只抽本期值（只看本期口径时 B 为 0.98，53 个标注数字里仅 1 个真正漏抽）。这两条都是设计取舍，不是"B 全面更好"。

无密钥时 `--mode demo` 的运行结果为：类型完全匹配 0.7143、关键数字 0.8906（本期 0.9344）、引用覆盖率 1.0000、无依据结论率 0.0526、平均 0.0024 秒。**这是规则引擎在合成样例上的结果，不是模型准确率。**

```bash
python evaluations/evaluate.py --mode demo     # 无需密钥，跑通流程
python evaluations/evaluate.py --mode llm      # 配置密钥后跑真实对比
python evaluations/evaluate.py --mode demo --limit 5
```

产物写入 `evaluations/results/`：`per_sample_results.csv`、`comparison.csv`、`metrics_summary.json`、`comparison_chart.png`。

**两条评分口径修正（写在这里，避免误读结果）**：① A 最初输出自由文本风险类型，与枚举标签严格相等比较必然判错，被记成 0.00；第二版只把标签词表同步给 A，其余条件不放宽。② 标注里的"2025 年度""1,200,000 股"会污染数字计数，已改为先剔除日期、去掉千分位再统计，A/B 同规则。两处修正都**降低**了 B 的表面优势。

## 七、安全与合规

- 公告文本被视为**不可信数据**：定界符包裹 + 定界符转义 + 系统消息声明三重隔离。测试 `test_injection_text_does_not_change_analysis` 验证了公告中出现"请忽略上述所有要求"时系统行为不变。
- 上传内容只在本次会话内存中处理，**不落盘**；除用户主动调用其自己配置的模型接口外，不外传任何数据。
- 自检环节会删除"建议买入/卖出/目标价/评级"等投资建议表述。
- 扫描件 PDF 不做 OCR，直接给出明确错误提示。

## 十、最终自检回答

| 问题 | 回答 |
| --- | --- |
| 应用能否在无 API 密钥时启动？ | **能**。自动进入演示模式，顶部橙色横幅标注，全部功能可用。 |
| 有 API 密钥时如何切换？ | 复制 `.env.example` 为 `.env` 填入 `LLM_BASE_URL`/`LLM_API_KEY`/`LLM_MODEL`，重启即可；也可在界面侧栏手动选"强制真实模型"。 |
| 一条结论如何追溯到原文？ | 结论携带 `evidence.quote`，经归一化后在清洗后原文中定位（精确包含→前缀→模糊，阈值 0.82），界面绿色"已验证证据"显示原文片段、匹配方式与相似度。 |
| 无法匹配证据时如何处理？ | 标为红色"未通过校验"，不作为依据展示；自检把该结论的"原文事实"降级为"推断"、等级降为信息不足、置信度下调、强制标记人工复核。 |
| 测试是否实际通过？ | **是**，`python -m pytest` 实际运行，82 项通过（本机 Python 3.13.14）。 |
| 哪些结果来自真实运行？ | 82 项测试、14 样本的真实模型评测（deepseek-chat，A/B 都跑）、界面截图，均为实际运行生成。 |
| 哪些仍待实测？ | 真实公告上的表现、更大规模标注集上的统计显著性、扫描件 OCR、向量检索带来的召回增益——均未验证。 |
| 是否包含密钥或隐私数据？ | **否**。`.env` 不提交，源码与产物中无密钥，界面只显示脱敏密钥。 |
| 哪些交付物尚不能由当前平台生成？ | 排版精确的 DOCX（模板要求的具体版式需本人粘贴到 Word 后设置；本交付提供 `docs/report_draft.md` 可直接粘贴）；截图需本人启动应用后补拍，或见 `docs/screenshots/`。 |
