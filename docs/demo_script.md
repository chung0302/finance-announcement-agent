# 课堂演示脚本（5~6 分钟逐字稿）

> 适用：最后一次课现场演示。
> 前提：提前执行 `python -m streamlit run app.py`，浏览器打开 http://localhost:8501 并**保持页面停在初始状态**。

## 0. 演示前准备清单（提前 5 分钟做完）

- [ ] 在项目目录执行 `python -m streamlit run app.py`，确认终端没有报错
- [ ] 浏览器打开 http://localhost:8501，确认页面正常显示
- [ ] 确认左侧栏是**蓝色**"已检测到模型配置"（橙色说明 `.env` 没生效，赶紧检查）
- [ ] 确认 `data/samples/` 下两个样例文件存在（利好 / 风险各一）
- [ ] 准备一份文本型 PDF（可用任意公告 PDF；**不要**用扫描件）
- [ ] 准备一段**当天现找的真实公告文本**（放在记事本里，用来证明结果不是写死的）
- [ ] 备用方案就绪：若现场断网或密钥失效，应用会自动降级为演示模式，界面变橙色，照常讲

---

## 第 1 段：问题背景（约 40 秒）

**【点击动作】** 不改页面，直接对着浏览器讲。

**【逐字稿】**

> 老师好，我做的作品叫《基于大语言模型的上市公司公告风险识别与解释助手》。
> 我想解决的问题很具体：上市公司公告动辄几千字，术语多、数字多，普通投资者很难快速看出
> 里面到底是业绩变好还是变坏、有没有股东减持、有没有诉讼和担保。
> 更麻烦的是，如果我们直接把公告丢给大模型问一句"有什么风险"，它可能会漏掉关键数字，
> 也可能会说出一些原文里根本不存在的话，也就是幻觉。
> 所以我的作品不是"问一句大模型"，而是设计一条流水线：先清洗、再结构化抽取、
> 结合知识库判定、每条结论都必须给出原文证据、最后再做一次自检。
> 界面上会明确区分"已验证证据"和"未通过校验"，拿不到证据的结论会被降级，
> 而不是假装很确定。

---

## 第 2 段：演示样例一 —— 偏利好（约 90 秒）

**【点击顺序】**

1. 左侧栏点击 **「▶ 载入利好样例」** 按钮
2. 上方输入框自动填入《星海智能科技股份有限公司 2026 年半年度业绩预告》
3. 点击 **「🚀 开始分析」**
4. 等待约 1 秒，结果出现

**【预期结果】**（本机 deepseek-chat 实测值，换模型会有出入）

- 顶部蓝色横幅：**真实模型模式（deepseek-chat），模型调用 3 次**（无密钥时为橙色"演示模式"）
- 四个指标卡：整体风险等级 **中**、置信度 **0.50**、已验证证据 **8 / 未通过 0**、用时约 **13 秒**
- 一句话结论：公司预计 2026 年上半年归母净利润 2.10 亿元，同比增长约 100%，主要来源于主营业务
- 结构化字段：公司名「星海智能科技股份有限公司」、标题「2026年半年度业绩预告」、日期「2026-07-15」、代码「301568」
- 事件类型：**业绩预增或扭亏**
- 关键指标表：归母净利润 2.10 亿元、扣非净利润 1.96 亿元、营业收入 18.60 亿元、非经常性损益 1400 万元等，每条显示 ✅ 已验证、相似度 1.00
- 风险条目：等级「中」，并提示预告数据未经审计、非经常性损益占比等不确定项

> 注意：等级是**中**而不是「低」。这是模型给的判断——业绩预增但不代表没有风险（预告未经审计、
> 增长可持续性存疑），正好用来讲"系统不会一味说好话"。

**【逐字稿】**

> 我先载入一个利好方向的样例。这是一份半年度业绩预告。
> 点「开始分析」，它要跑六步流水线，其中三次调用模型，大概十几秒。
> 趁这个时间说一下：直接问大模型一次大概 2 秒，我这里要 11 秒多，
> 多出来的时间就是抽取、判定、自检三次调用和证据校验的成本——也就是可核验性的价格。
> 大家看结果：事件类型是"业绩预增或扭亏"，
> 关键金额抽到了 2.10 亿元、1.96 亿元、18.60 亿元、非经常性损益 1400 万元，每条后面都显示"已验证"。
> 这个"已验证"不是模型自己说的，是系统把这段原文拿回到清洗后的公告里做匹配，
> 匹配上了才允许作为依据展示。
> 另外注意整体等级判的是"中"而不是"低"：虽然业绩翻倍，但预告数据未经审计，
> 增长里有多少来自非经常性损益也没说清，系统把这些放进了"不确定性"。
> 这就是我想做的"有依据的谨慎"，而不是一味说好话或一味吓人。

## 第 3 段：演示样例二 —— 偏风险（约 100 秒）

**【点击顺序】**

1. 左侧栏点击 **「▶ 载入风险样例」**
2. 确认输入框换成了《华岭新材料股份有限公司 关于控股股东减持股份计划的公告》
3. 点击 **「🚀 开始分析」**
4. 展开第一条风险条目，指着"已验证证据"讲；再翻到「信息不足提示」

**【预期结果】**

- 整体风险等级 **高**（取两条风险中的最高者）
- 事件类型命中两个：**股东或高管减持**、**重大诉讼或仲裁**
- 第一条风险：等级「高」、置信度 0.65，原因写明"减持主体为控股股东，比例 1.50% 超过知识库中 1% 的高风险参考线"
- 第二条风险（诉讼）：等级「信息不足」、置信度 0.35，因涉案金额占净资产比例未披露
- 证据清单：绿色"已验证"框，标注相似度 1.00
- 信息不足提示：约 9 条（涉案金额占比、减持价格区间、是否计提预计负债等），其中两条带"需人工复核"
- 底部自检区：显示自检问题表（字段 / 问题 / 处理动作 / 级别）

**【逐字稿】**

> 第二个样例是风险方向的：控股股东减持。
> 系统给出了两个风险标签——减持和诉讼。减持这条判为"高"风险，
> 原因是知识库里有一条规则：减持主体如果是控股股东、或者单次比例超过总股本 1%，
> 就要上调等级。这份公告里两个条件都满足：主体是控股股东，比例 1.5%。
> 而这个"1.5%"不是我写死的，是从原文里抽出来的，后面挂着原文片段。
> 诉讼这条判的是"信息不足"而不是硬判"中"或"高"，因为一审还没判，
> 而且公告没写涉案金额占净资产的比例，重大性根本没法量化。
> 所以系统在"信息不足提示"里把这条明确写出来，并标记"需人工复核"。
> 我想强调这一块：**不知道就说不知道**。系统宁可把等级写成"信息不足"、
> 把置信度降到 0.35，也不会硬编一个结论。

## 第 4 段：证据校验与防幻觉（约 60 秒）

**【点击顺序】**

1. 滚到「原文证据清单」
2. 指绿色"已验证"框；如果有红色"未通过校验"框就指红色框
3. 滚到页面底部「导出」，点一次 **「⬇️ 导出 Markdown 报告」**（下载即可，不必打开）

**【逐字稿】**

> 这是整个作品最核心的一块：证据校验。
> 每一条风险结论都必须带一段原文引用，系统会把这段引用做归一化——
> 统一全角半角、去掉空格换行、统一标点——然后回到清洗后的公告原文里去找。
> 先精确匹配，再前缀匹配，最后做模糊匹配，相似度超过 0.82 才算通过。
> 通过的是绿色"已验证"，没通过的是红色"未通过校验"，
> 红色的不会被当成有效依据，对应的结论会被自检环节降级、并且强制标记人工复核。
> 这一步就是防幻觉的关键：**没有原文支撑的结论，系统自己就会把它打回去。**
> 最后点这里可以导出 Markdown 报告，里面包含所有字段、证据和自检记录，
> 也可以导出 JSON 给程序用。

---

## 第 5 段：上传文件与错误处理（约 50 秒）

**【点击顺序】**

1. 切到 **「② 上传 PDF / TXT」** 标签页
2. 上传准备好的文本型 PDF（或 TXT）
3. 成功时展示"已读取 xxx 字符"
4. 若时间允许：再上传一张截图转成的 PDF（扫描件），展示明确报错

**【预期结果】**

- 文本型 PDF：绿色提示"已读取 X 字符，共 N 页"，可展开看原文
- 扫描件 PDF：红色错误"该 PDF 没有可提取的文本层（可能是扫描件或图片版），本工具不做 OCR"

**【逐字稿】**

> 除了粘贴，也支持上传 PDF 和 TXT。这里我做了一个明确的边界：
> 只支持文本型 PDF，扫描件我不做 OCR，也不假装能做——
> 遇到没有文本层的 PDF，界面会直接给出一条明确错误，而不是返回一堆乱码或者空结果。
> 另外，空输入、模型超时、模型返回非法 JSON 这几种情况都有对应的处理，
> 我在单元测试里都覆盖了，一共 82 项测试。

---

## 第 6 段：收尾（约 30 秒）

**【逐字稿】**

> 总结一下：这个作品做了三件事——把长公告变成结构化字段、把风险判断和原文证据绑定、
> 把不知道的部分明确说出来。它不做股价预测，也不给买卖建议，
> 自检环节发现"建议买入/卖出"这类措辞会直接删掉。
> 局限也要说明：样本是我自己构造的演示文本，不是真实公告，只有 14 份，
> 不足以支撑统计结论。我用同一套样本对比了"直接问大模型"和"这套工作流"：
> 类型判定和工作流这边更好，1.00 对 0.79；但数字召回上直接问反而更好，1.00 对 0.92；
> 工作流的真正增量在"每条结论都能回到原文"——引用覆盖率 1.00 对 0.00，
> 代价是慢 5.6 倍。所以我不敢说它全面更好，只能说它换到了可核验性。

## 备用方案（现场出问题时按此切换）

| 意外情况 | 应对 |
| --- | --- |
| Streamlit 起不来 | 直接展示 `docs/screenshots/` 下的截图 + `evaluations/results/comparison.csv` |
| 端口被占用 | 换端口：`python -m streamlit run app.py --server.port 8502` |
| 现场断网 / 密钥失效 | 全程演示模式（本来就是默认路径），照常讲，说明"这是规则引擎结果，已标注" |
| 上传 PDF 报错 | 这是**预期内的正确行为**（扫描件），正好用来讲错误处理这一节 |
| 时间不够 6 分钟 | 只讲第 1、2、3、6 段（约 4 分钟），证据校验那一页用截图带过 |
| 想展示"未通过校验"的红色效果 | 粘贴一段不含任何风险关键词的文本（如一段会议通知），系统会给出"信息不足" |
