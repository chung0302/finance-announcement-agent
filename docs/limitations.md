# 局限性与已知问题

> 本文件如实列出本作品当前做不到的地方。课堂汇报与答辩时建议主动说明这些局限，
> 这比事后被追问更稳妥。所有条目均为实际存在的限制，不含虚构内容。

## 1. 数据层面

| 局限 | 具体说明 | 影响 |
| --- | --- | --- |
| **样本为合成文本** | `data/samples/` 下 14 份文本全部由本人构造，公司、代码、事件、数字均虚构 | 不能外推到真实公告；合成文本表述规整，指标会系统性偏高 |
| **样本量不足** | 远低于计划中的 20~30 份，更不足以支撑统计显著性检验 | 无法给出置信区间，只能报告点估计 |
| **未取得授权原文** | 巨潮资讯、上交所、深交所的公告原文在本次运行环境下无法稳定批量获取 | 无法验证真实公告上的实际表现 |
| **标注为单人完成** | 无第二标注人，未计算标注一致性（如 Kappa） | 标注质量未经过交叉检验 |

## 2. 方法层面

| 局限 | 具体说明 | 影响 |
| --- | --- | --- |
| **风险类型只覆盖 6 类** | 长尾事项（如股权激励、并购重组、关联交易、分红）落入"其他重大事项"或"未识别" | 覆盖面有限，不能当作通用公告分析工具 |
| **等级规则是人为设定** | 如"减持比例 1%""涉案金额占净资产 10%"等阈值来自对披露规则的通行理解，非法定标准 | 阈值合理性未经监管口径校验 |
| **证据匹配基于字符相似度** | 阈值 0.82，对大幅改写、跨句拼接的引用可能误判 | 存在漏判（真证据被判不通过）与误判（伪证据被判通过） |
| **演示模式是规则引擎** | 无密钥时跑的是正则 + 触发词，不是大模型 | 演示模式的数值**不能**称为模型效果 |
| **真实模型只在单一模型上测过** | 2026-11-04 用 deepseek-chat（温度 0）跑完 14 个样本，A/B 都跑了 | 换模型、换温度都可能变；结论只对这个配置成立 |
| **数字召回不如直接问模型** | A 把数字全列一遍，召回 1.00；B 受 Schema 与"只抽本期"约束，0.92（本期口径 0.98） | B 的增量在可追溯性，不在召回率，别写成"全面更优" |
| **延迟明显更高** | 单样本 11.56 秒（A 为 2.05 秒），因为每个样本 3 次模型调用 + 证据校验 | 交互体验受限，长公告会更慢 |

## 3. 工程层面

| 局限 | 具体说明 |
| --- | --- |
| **不支持扫描件 OCR** | 无文本层的 PDF 直接返回明确错误，不做识别 |
| **长公告会截断** | 送入模型的文本上限 `MAX_INPUT_CHARS=12000` 字符，超长公告只分析前段（证据校验仍在全文上进行） |
| **无用户与数据持久化** | 按 MVP 范围刻意不做登录、权限、数据库；上传内容只在本次会话内存处理，刷新即丢失 |
| **无并发与性能设计** | 单次请求串行执行，未做缓存与批处理 |
| **中文分词与语义检索缺失** | 知识库检索为关键词加权，未使用向量模型，召回依赖关键词命中 |
| **规则抽取依赖版式假设** | 表格型的"本期数 / 上年同期数"两列必须专门识别，否则会把上年数当本期值。本轮已修掉三类真实缺陷（上年同期被当本期、表格中重复的数据行被误当页眉删除、页眉去重把证券代码整体删光），并补了回归测试；但真实公告版式更杂，仍会出现新的错配 |
| **股数与比例容易混淆** | 减持公告同时出现"持股数量 152,000,000 股 / 持股比例 38.00% / 拟减持数量 / 减持比例 1.50%"，名称靠上下文关键词推断，长句或跨行排版下仍可能张冠李戴 |

## 4. 安全与合规层面

- 本作品**不预测股价、不提供买卖建议**；自检环节会删除"建议买入/卖出/目标价/评级"类表述，但无法保证覆盖所有变体说法。
- 公告文本被视为不可信输入并做了定界符 + 转义 + 系统声明三重隔离，但**提示词注入无法被彻底消除**，只能降低发生概率。
- 模型接口由使用者自行配置，文本会发送至该接口；若使用境外服务，需注意数据出境与合规问题。**本作品不代管任何密钥**。
- 分析结果可能存在错误，投资决策必须以公司正式披露文件为准。

## 5. 未验证事项清单（报告与答辩中不得写成"已完成"）

1. 真实上市公司公告上的表现 —— **未验证**（全部样本为合成文本）
2. 更大标注集上的统计显著性 —— **未验证**（14 个样本只能给点估计，不能给置信区间）
3. 提示词 v2 相对 v1 的量化提升 —— **未做量化对比**，仅有失败样例的人工归纳
4. 扫描件 OCR、向量检索带来的召回增益 —— **未实现/未验证**
5. 多模型横向比较（如 gpt-4o-mini、qwen） —— **未做**，只测了 deepseek-chat
