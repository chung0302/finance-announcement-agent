# 答辩展示提纲（总时长约 5 分钟）

> 配合 `docs/demo_script.md` 使用：本文件管"讲什么、讲多久"，演示脚本管"点哪里、说什么"。

---

## 一、30 秒 · 问题背景

**核心一句话**：公告太长、术语太多，直接问大模型又容易漏数字、说瞎话。

**要讲的三点**

1. 现实痛点：一份业绩预告/减持公告动辄数千字，普通投资者要找的是"公司、日期、事件、金额、同比变化"这几项，人工翻阅成本高。
2. 直接问大模型的问题：可能漏关键数字；可能生成原文没有的结论（幻觉）；不知道的时候会硬答。
3. 本作品的定位：**只做信息提取与风险提示**，不预测股价、不给买卖建议。

**过渡句**：所以我做的不是一个"问答框"，而是一条带证据回溯的流水线。

---

## 二、1 分钟 · 系统架构

**照着架构图讲六步**（`docs/architecture.md` 里有 Mermaid 图和文字版）

| 步骤 | 一句话 | 防的是什么 |
| --- | --- | --- |
| ① 文本清洗 | 合并 PDF 断行、删重复页眉页脚、统一全半角 | 排版噪声导致抽取错位 |
| ② 信息抽取 | 固定 JSON Schema，数字保留原文写法 | 模型自由发挥、单位被换算 |
| ③ 知识检索 | 6 类风险定义 + 判定规则 + 术语 + 示例 | 判定标准靠模型临场发挥，不可复现 |
| ④ 风险识别 | 事实 / 推断 / 不确定性 三段式 | 把猜测包装成事实 |
| ⑤ 证据校验 | 归一化后回原文定位，相似度 ≥0.82 | 无依据结论（幻觉） |
| ⑥ 二次自检 | 公司/日期/金额/事件一致性 + 投资建议清理 | 数字张冠李戴、越界输出 |

**要点强调**

- 知识库**只作参考**，是否成立必须有原文证据；
- 证据校验失败的结论会被**降级 + 标记人工复核**，而不是直接丢弃或假装有效；
- 公告文本被视为**不可信数据**，用定界符 + 转义 + 系统声明三重隔离；
- 无 API 密钥时自动进入**演示模式**并强制标注，应用本身照常启动。

**过渡句**：下面我实际跑两个样例给大家看。

---

## 三、2 分钟 · 现场演示

**先花 30 秒证明"不是写死的"**（这一步最关键，放在最前面）

从巨潮资讯或任意财经 App 当天的公告里复制一段没见过的正文，粘贴进去，现场等 10~15 秒出结果。
话术：

> "这段公告不在我的样例库里，是我今天现找的，大家看它抽出来的公司名、金额和结论——
> 如果结果是写死的，换一段文本就会露馅。"

备选（没网也能做）：让对方口头念一段公告里的句子，自己打进去。真实模型掉线时会自动降级，
界面立刻变成橙色"演示模式"，规则引擎照样能抽字段——**降级本身也要指给评委看**。

**样例一（利好，约 40 秒）**：半年度业绩预告 → 抽出 2.10 亿元 / 1.96 亿元 / 18.60 亿元 / 非经常性损益 1400 万元，六项指标全部"已验证"，同时提示"增长是否来自主营业务未说明"。
→ 说明系统**不会盲目乐观**。

**样例二（风险，约 60 秒）**：控股股东减持公告 → 减持那条判「高」（控股股东 + 1.5% > 1% 参考线），诉讼那条因金额占净资产比例未披露判「信息不足」并标记人工复核。
→ 说明系统**不会硬编结论**。

**演示过程中必须指给评委看的三处**

1. 绿色「已验证证据」框 + 相似度数字；
2. 「信息不足提示」区；
3. 顶部模式横幅（真实模型模式 / 演示模式）。

**等结果的 10 秒不要干站着**：就说"它在跑三次模型调用——抽取、判定、自检，所以比直接问一句慢，
慢的部分就是可核验性的成本"。

## 四、1 分钟 · 评测结果

**评测设计**：A 方案 = 普通大模型直接总结（`prompts/baseline_summary.md`，无 Schema / 无知识库 / 无证据校验）；
B 方案 = 本作品工作流。脚本 `evaluations/evaluate.py` 可复现，输出 CSV / JSON / 图表。

**五项指标**：风险类型识别准确率、关键数字提取正确率、引用覆盖率、无依据结论率、平均响应时间。

**现场怎么讲（重要：如实汇报）**

已配置密钥并跑过 `--mode llm`，直接读 `evaluations/results/comparison.csv` 的数字，
说明"这是本人在本机、deepseek-chat、温度 0 下实测的结果，换模型会变"。

**可以报的数字（14 个样本）**

- 风险类型完全匹配：B **1.00**，A **0.79**（A 错在给一例"资金占用"多挂了"审计意见异常"标签）
- 关键数字提取正确率：B **0.92**，A **1.00**——**A 更好，要主动说出来**；只看本期口径 B 是 0.98，53 个标注数字仅 1 个真漏抽
- 引用覆盖率：B **1.00**（74 条证据全部通过校验），A **0.00**
- 无依据结论率：B **0.00**，A **1.00**（定义使然：A 根本不产可定位引文）
- 平均响应时间：B **11.56 秒**，A **2.05 秒**

**一句话总结**：B 买到的是"每条结论都能回到原文"，代价是 5.6 倍延迟和略低的数字召回。
不要说成"B 全面优于 A"——评委一问数字召回就露馅。

**主动交代的两处口径修正**（很加分）：A 初版自由文本 vs 枚举标签做严格相等，被误判成 0.00，
第二版只统一标签词表；标注里的"2025 年度""1,200,000 股"污染计数，已剔除日期与千分位。
两处修正都让 B 的数字**变差**，但只有公平口径才值得讨论。

## 五、30 秒 · 局限与收获

**局限（主动讲，不藏）**

1. 样本是**合成演示文本**，非真实公告，规模仅 14 份，不足以支撑统计结论；
2. 规则引擎只能覆盖 6 类风险，长尾事项会落到"其他重大事项/未识别"；
3. 扫描件 PDF 不做 OCR；
4. 证据匹配基于字符相似度，对大幅改写仍可能误判。

**收获（个人化，【请填写】处由本人补充）**

- 技术：把一个"调用 API"的想法拆成可验证的流水线；理解了提示词工程、Schema 约束、证据回溯的价值。
- 认知：财经场景里"不知道"比"编一个答案"更有价值；可解释性本身就是产品功能。
- 【请填写：你个人最想补充的一点体会】
